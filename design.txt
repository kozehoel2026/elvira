1. ОПИС ОРГАНІЗАЦІЇ
---------------------------------------------------------------------
«Солодкий куточок» — невелика кав'ярня, яка продає десерти власного
виготовлення (торти, тістечка, макарон, чізкейки, круасани тощо).
Гості купують десерти в залі або на виніс. Працює 3-5 працівників:
власник/адміністратор і кілька касирів-бариста.


2. АНАЛІЗ ТИПОВИХ БІЗНЕС-ПРОЦЕСІВ
---------------------------------------------------------------------
 №  Процес                    Опис                           Зараз
--- ------------------------- ------------------------------ ---------
 1  Закупівля сировини        Замовлення борошна, вершків,   вручну
                              шоколаду у постачальників
 2  Виробництво десертів      Кондитер готує десерти,        вручну
                              записує кількість у зошит
 3  Ведення меню (асортимент) Додавання нових десертів,      вручну
                              зміна цін, вивіска в залі
 4  Продаж (оформлення        Касир приймає замовлення,      вручну/
    замовлення)               рахує суму, приймає оплату     калькулятор
 5  Облік залишків            Скільки десертів лишилось      вручну
                              на вітрині
 6  Звітність                 Виручка за день, популярні     вручну,
                              десерти                        Excel

Проблеми ручного ведення:
 - помилки в підрахунку суми та залишків;
 - касир не знає, чи є десерт у наявності, поки не перевірить вітрину;
 - власнику важко дізнатись виручку та популярні позиції;
 - меню в залі доводиться переписувати при кожній зміні ціни.


3. ЕТАПИ, ОБРАНІ ДЛЯ АВТОМАТИЗАЦІЇ
---------------------------------------------------------------------
Автоматизуються процеси, пов'язані безпосередньо з продажем:

 [A] Ведення меню (процес 3)
 [B] Продаж — оформлення замовлення (процес 4)
 [C] Облік залишків десертів (процес 5)
 [D] Звітність про продажі (процес 6)

Закупівля та виробництво залишаються поза межами системи (можуть бути
наступним етапом розвитку). Кондитер лише повідомляє адміністратора,
скільки десертів приготовано, а той поповнює залишок у системі.

Схема автоматизованого процесу продажу:

  Гість обирає   ->  Касир додає  ->  Система    ->  Касир   ->  Система
  десерт у меню      позиції до      перевіряє      оформлює    списує
                     замовлення      залишок і      замовлення  залишок,
                                     рахує суму                  зберігає
                                                                 продаж

6. АРХІТЕКТУРА СИСТЕМИ
---------------------------------------------------------------------
Тип: класична трирівнева клієнт-серверна веб-архітектура (MVC-подібна).

  +-----------------------------------------------------------+
  |  РІВЕНЬ ПРЕДСТАВЛЕННЯ (клієнт)                             |
  |  Браузер на ПК / планшеті / смартфоні                     |
  |  HTML5 + CSS3 (responsive, Flexbox/Grid, media queries)   |
  |  JavaScript-модулі (кошик, виділення десертів, підтверд.) |
  +-----------------------------+-----------------------------+
                                | HTTP (GET / POST, форми)
  +-----------------------------v-----------------------------+
  |  РІВЕНЬ ЛОГІКИ (сервер)                                    |
  |  Node.js 22+ (сучасний JavaScript, ES-модулі)             |
  |   - server.js   : HTTP-сервер, точка запуску              |
  |   - src/routes/ : маршрути (controllers)                  |
  |   - src/db.js   : робота з базою даних                    |
  |   - src/views/  : шаблони сторінок (views)                |
  |   - сесії в Map, хешування паролів (scrypt, node:crypto)  |
  +-----------------------------+-----------------------------+
                                | SQL (модуль node:sqlite)
  +-----------------------------v-----------------------------+
  |  РІВЕНЬ ДАНИХ                                              |
  |  SQLite — один файл cafe.db                                |
  +-----------------------------------------------------------+

Обрані технології та чому:
 - Node.js + сучасний JavaScript — одна мова на сервері й у браузері,
   лише вбудовані модулі (node:http, node:sqlite, node:crypto),
   жодних сторонніх бібліотек.
 - Структури даних: Map (маршрути, сесії, кеш SQL-запитів, позиції
   чека), Set (дозволені формати фото, ролі, вибрані десерти),
   масиви з map/filter/reduce, Object.freeze для констант.
 - SQLite — не потребує окремого сервера БД, база в одному файлі.
 - Шаблони — теговані шаблонні рядки html`...` з автоматичним
   екрануванням (захист від XSS).
 - Чистий CSS без фреймворків — адаптивний дизайн через media queries.
 - Без ORM — прямі SQL-запити, щоб було видно, як працює база.

Структура проєкту:
 cafe_desserts/
 ├── server.js          головний файл, запуск сервера
 ├── package.json       опис проєкту (npm start)
 ├── src/               серверний код: routes/, views/, core/, db.js
 ├── schema.sql         SQL-опис таблиць
 ├── read.me            опис та інструкція запуску
 ├── design.txt / .html цей проєкт
 ├── ER.jpg             ER-модель даних
 ├── cafe.db            база даних (створюється автоматично)
 ├── static/style.css   стилі (responsive)
 ├── static/img/desserts/  фото десертів
 └── static/js/         скрипти для браузера


7. МОДЕЛЬ ДАНИХ (сутності)
---------------------------------------------------------------------
 users        — користувачі системи
   id PK, username (унікальний), password_hash, full_name,
   role ('admin' | 'cashier'), created_at

 categories   — категорії десертів
   id PK, name (унікальна)

 desserts     — десерти в меню
   id PK, category_id FK -> categories.id, name, description,
   price, stock (залишок, шт.), is_active (1/0),
   image (ім'я файлу фото в static/img/desserts/)

 orders       — замовлення (чек)
   id PK, user_id FK -> users.id (касир, який оформив / видав;
   NULL, поки замовлення клієнта не видане), created_at, updated_at,
   total, status ('new' | 'ready' | 'done' | 'cancelled'),
   customer_note, source ('staff' | 'kiosk'), customer_name,
   token (секретний ключ сторінки відстеження)

 order_items  — позиції замовлення
   id PK, order_id FK -> orders.id, dessert_id FK -> desserts.id,
   quantity, price (ціна на момент продажу)

Зв'язки:
 categories 1 —— N desserts
 users      1 —— N orders
 orders     1 —— N order_items
 desserts   1 —— N order_items
 (orders і desserts пов'язані «багато-до-багатьох» через order_items)

9. НЕФУНКЦІОНАЛЬНІ ВИМОГИ
---------------------------------------------------------------------
 - Адаптивний інтерфейс: смартфон (від 360 px), планшет, ПК.
 - Інтерфейс українською мовою.
 - Паролі зберігаються лише у вигляді хешу.
 - Захищені сторінки недоступні без входу; права перевіряються
   на сервері.
 - Запуск на будь-якому ПК з Node.js 22.13+ однією командою.
