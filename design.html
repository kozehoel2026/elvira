Автоматизована система кав'ярні «Солодкий куточок»

Проєкт системи продажу десертів · курсова робота, 1 курс, «Веб-технології»

1. Організація

Невелика кав'ярня, що продає десерти власного виготовлення (торти, тістечка, макарон, чізкейки, круасани) у залі та на виніс. Персонал: власник-адміністратор і кілька касирів-бариста.

2. Типові бізнес-процеси

№ПроцесОписАвтоматизація
1Закупівля сировиниЗамовлення продуктів у постачальниківні
2ВиробництвоКондитер готує десертині
3Ведення менюАсортимент, ціни, категоріїтак [A]
4ПродажОформлення замовлення, підрахунок сумитак [B]
5Облік залишківКількість десертів на вітринітак [C]
6ЗвітністьВиручка, популярні десертитак [D]

Проблеми ручного ведення: помилки в сумах і залишках, касир не знає наявності, власнику важко отримати виручку, меню доводиться переписувати.

Автоматизований процес продажу:

Гість обирає десерт→Касир додає в замовлення→Система перевіряє залишок і рахує суму→Оформлення→Списання залишку, збереження продажу

Самообслуговування (як у кіоску McDonald's):

Клієнт обирає десерти в меню→Оформлює замовлення й отримує номер→Замовлення з'являється в черзі касира→Касир: «Готове» — клієнта кличуть→Оплата на касі, «Видано»

3. Ролі користувачів

Гість

Будь-який відвідувач. Переглядає меню, сам оформлює замовлення без входу й стежить за його статусом.

Касир

Бариста за касою. Оформлює замовлення, переглядає замовлення.

Адміністратор

Власник. Усе, що касир, + меню, залишки, категорії, користувачі, звіти, скасування.

5. Архітектура

Трирівнева клієнт-серверна веб-архітектура (MVC-подібна).

Рівень представлення — браузер (ПК, планшет, смартфон): HTML5, CSS3 (Flexbox/Grid, media queries), JavaScript-модулі (живий чек, виділення десертів при натисканні).
↕ HTTP (GET / POST, форми)
Рівень логіки — Node.js 22+ (сучасний JavaScript, ES-модулі): сервер server.js, маршрути src/routes/, робота з БД src/db.js, шаблони src/views/, сесії, хешування паролів (scrypt).
↕ SQL (вбудований модуль node:sqlite)
Рівень даних — SQLite, один файл cafe.db.

Чому так: Node.js — одна мова (JavaScript) і на сервері, і в браузері, без сторонніх бібліотек; Map і Set — для швидкого пошуку; SQLite — без окремого сервера; чистий CSS без фреймворків; прямі SQL-запити без ORM, щоб було видно роботу бази.

6. Модель даних

ТаблицяПоля
usersid PK, username, password_hash, full_name, role (admin/cashier), created_at
categoriesid PK, name
dessertsid PK, category_id FK, name, description, price, stock, is_active, image (файл фото)
ordersid PK, user_id FK (може бути NULL до видачі), created_at, updated_at, total, status (new/ready/done/cancelled), customer_note, source (staff/kiosk), customer_name, token
order_itemsid PK, order_id FK, dessert_id FK, quantity, price

Зв'язки: categories 1:N desserts · users 1:N orders · orders 1:N order_items · desserts 1:N order_items (orders ↔ desserts — M:N через order_items).
